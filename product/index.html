What the product does, grouped by capability — not by which file implements it. Each area is tagged with the vision goal(s) it serves (not every area needs one, and not every goal needs an area yet), a status pill for its own activity (stable = shipped, no active work · in development · blocked · backlog), and each feature is tagged with the file(s) it touches plus a dot for whether it came from a deliberate user story or something bumped into along the way.

The process and dev-ops side: how this repo actually gets worked on. Grounded in real files — gaps are flagged honestly, not invented.

What the reading app's cabinet wall is actually made of, component by component — the vitrine, the wall-head, the key, and one growth-area stack of drawers. The numbered pins sit directly on the feature they name; read the matching row alongside.

  1. Vitrine — reviews due, latest accession, where you left off.
  2. Wall-head — running count of visible drawers and specimens.
  3. Area chips — click to solo a growth area, shift-click to add.
  4. Key — collapsible legend for the encodings below it.
  5. Stack — one growth area, sorted new → evolving → live → retiring.
  6. Drawer — one chapter; face depth signals reading length.
  7. Specimen plate — concept glyph tinted to the growth-area ink color.
  8. Baize seam — green left edge means ajar: new or revised.
  9. Read line — brass line at the foot is progress read; a struck title (row 3 in the stack above) marks retiring.
